# Release actions and registry target

Updated 6 October 2026 for the [simplified repository policies](../rector_review_2026-10/dabar_simple_2026-10-06/README.md). The repository administrator authorises accounts and collection permissions and provides technical support. Authorised institutional depositors publish directly; no mandatory review queue, assigned reviewer or administrator sign-off is required.

1. Identify a responsible human compiler/depositor for one genuine package and an account authorised for its intended collection. Confirm the compilation fits the collection and accurately distinguishes source-study authors from the compiler.
2. The depositor confirms source/third-party authority, documentation, attribution, file licence and access conditions, then completes the normal DSpace deposit terms. Use the package checklist and [release decisions](release_decisions.json); remove no source-rights or privacy holds merely because the workflow is simpler.
3. When publication is explicitly authorised, deposit actual data and documentation as a separate record linked to its publication. Verify the real landing page, intended anonymous access, file checksums and metadata exports. Continue the existing approved Handle workstream.
4. Support the approximately 9–10 October re3data target with actual public service/operator/access/terms evidence and update existing FAIRsharing [9313](https://fairsharing.org/9313) when authorised. Backlog completion is not a submission prerequisite; local packages are not public holdings and registry acceptance timing is unknown.

Three packages remain prepared locally; none was publicly deposited by this work. Production permissions and collection workflows have not been changed. If a collection currently has an approval step, its administrator must reconfigure it for direct deposit; account permissions alone do not remove that step.
